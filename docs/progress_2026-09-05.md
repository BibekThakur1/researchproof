## Observations

The rule baselines and all three learned feature settings classified every current case correctly. The learned models were not perfectly calibrated: aggregate expected calibration error was approximately 0.116 for static evidence, 0.235 for runtime evidence, and 0.096 for hybrid evidence in this run.

These numbers are **engineering observations, not research findings**. The benchmark currently names operations such as `preprocessing_fit_all_rows`, which exposes the injected mechanism. Perfect classification therefore shows that the pipeline and evaluation code are connected correctly; it does not show that ResearchProof can understand realistic notebooks or unseen coding styles.

All 45 counterfactual repairs passed the current mechanical checks: the paired identity and base split were preserved, while the explicit static and runtime fault markers disappeared. This validates the repair harness only. A meaningful repair evaluation must later verify semantic task preservation on independently authored pipelines.

## Decision

Do not train a larger model or report accuracy from benchmark version 0.2. The next benchmark version must replace label-revealing operation names with evidence derived from realistic source code and runtime row lineage. It must also contain multiple independently written pipeline templates and difficult clean examples that resemble faulty orderings without violating the evaluation protocol.

## Next acceptance criteria

1. At least three syntactically different templates per fault family.
2. No feature name may encode the gold label or injector name.
3. Complete template families must be held out during evaluation.
4. Clean hard-negative cases must include refitting, cross-validation, nested pipelines, and harmless full-data operations.
5. Two reviewers must label a blinded sample and document disagreements.

## Later work completed on the same milestone

A source-code pilot now contains 18 clean/faulty snippets across three naming styles.
An AST baseline is evaluated by leaving one complete naming style out. It also
classified all pilot snippets correctly, confirming that variable-name changes alone
are not a meaningful generalization test. The repository now exports these cases as
opaque files for two independent reviewers and can calculate raw agreement, Cohen's
kappa, and a disagreement list after both forms are complete.

Paired bootstrap summaries were added for the 45 clean/faulty run pairs. In the
current engineering run, the overall mean accuracy difference (faulty minus clean)
was approximately 0.00194, with a 95% bootstrap interval from approximately -0.00094
to 0.00520. This near-zero aggregate effect is useful negative evidence: the current
fault strengths and datasets do not yet demonstrate practically important score
inflation. Future cases must vary leakage severity and include settings where the
invalid method can plausibly alter conclusions. These values must not be cited as a
paper result until the benchmark and analysis plan are frozen and independently
reproduced.
