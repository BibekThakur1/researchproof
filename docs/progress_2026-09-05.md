## Observations

The rule baselines and all three learned feature settings classified every current case correctly. The learned models were not perfectly calibrated: aggregate expected calibration error was approximately 0.116 for static evidence, 0.235 for runtime evidence, and 0.096 for hybrid evidence in this run.

These numbers are **engineering observations, not research findings**. The benchmark currently names operations such as `preprocessing_fit_all_rows`, which exposes the injected mechanism. Perfect classification therefore shows that the pipeline and evaluation code are connected correctly; it does not show that ResearchProof can understand realistic notebooks or unseen coding styles.

All 45 counterfactual repairs passed the current mechanical checks: the paired identity and base split were preserved, while the explicit static and runtime fault markers disappeared. This validates the repair harness only. A meaningful repair evaluation must later verify semantic task preservation on independently authored pipelines.

## Decision

Do not train a larger model or report accuracy from benchmark version 0.2. The next benchmark version must replace label-revealing operation names with evidence derived from realistic source code and runtime row lineage. It must also contain multiple independently written pipeline templates and difficult clean examples that resemble faulty orderings without violating the evaluation protocol.

## Next acceptance criteria

1. At least three syntactically different templates per fault family.
2. No feature name may encode the gold label or injector name.
3. Complete template families must be held out during evaluation.
4. Clean hard-negative cases must include refitting, cross-validation, nested pipelines, and harmless full-data operations.
5. Two reviewers must label a blinded sample and document disagreements.

## Later work completed on the same milestone

A source-code pilot now contains 18 clean/faulty snippets across three naming styles.
An AST baseline is evaluated by leaving one complete naming style out. It also
classified all pilot snippets correctly, confirming that variable-name changes alone
are not a meaningful generalization test. The repository now exports these cases as
opaque files for two independent reviewers and can calculate raw agreement, Cohen's
kappa, and a disagreement list after both forms are complete.

Paired bootstrap summaries were added for the 45 clean/faulty run pairs. In the
current engineering run, the overall mean accuracy difference (faulty minus clean)
was approximately 0.00194, with a 95% bootstrap interval from approximately -0.00094
to 0.00520. This near-zero aggregate effect is useful negative evidence: the current
fault strengths and datasets do not yet demonstrate practically important score
inflation. Future cases must vary leakage severity and include settings where the
invalid method can plausibly alter conclusions. These values must not be cited as a
paper result until the benchmark and analysis plan are frozen and independently
reproduced.

## Benchmark-hardening update

Benchmark version 0.3 introduces low, medium, and high contamination settings. It
contains 270 executable cases and 135 clean/faulty repair contrasts. All 135 repairs
passed the current mechanical verifier. Mean accuracy differences increased with the
requested severity in this engineering run: approximately 0.00020 at low severity,
0.00199 at medium severity, and 0.00857 at high severity. Clean controls are reused
across related severity contrasts, so they must not be treated as independent samples.

The source pilot now includes nine valid hard negatives, for 27 snippets in total.
Leaving out a naming style still produced perfect classification, confirming that
renaming variables is a weak test. Leaving out complete structural templates reduced
aggregate accuracy to approximately 0.667 and F1 to 0.400, with six missed faulty
cases and three false alarms. This is the first useful failure signal from the static
pilot: the current AST bag-of-calls baseline does not generalize reliably to unseen
pipeline structures. The sample remains one-author and small, so this observation is
a design input rather than a publishable result.

A fresh clone from GitHub was also tested in a new virtual environment created only
from the pinned dependency file. It passed all 60 tests, regenerated 270 cases, and
matched the original benchmark on every compared scientific field. Runtime was the
only ignored field. This establishes same-machine clean-checkout reproducibility, not
independent-machine reproduction; the second researcher's laptop remains necessary.

Helper-function indirection was then added deliberately as a robustness challenge.
The source pilot now has 36 cases. The bag-of-AST-calls baseline reached approximately
0.972 accuracy and 0.957 F1 under naming-style holdout, but remained at approximately
0.667 accuracy and 0.400 F1 under structural-template holdout. The symbolic provenance
baseline reached approximately 0.917 accuracy and 0.857 F1, missing all three faulty
helper-indirection cases while producing no false alarms on the current clean cases.
This localizes a concrete next technical problem: interprocedural provenance across
user-defined helper functions. Solving that problem should be evaluated on independent
templates rather than only adding special cases to the current analyzer.

A generic first-pass function-summary analysis was subsequently implemented. It
propagates argument provenance through simple single-return helper functions and does
not depend on the helper names used by the templates. It detects all 12 current faulty
source cases while retaining zero false alarms on the 24 current clean cases. This
closes the known helper examples but does not establish interprocedural generalization:
nested helpers, branches, loops, mutation, dataframe methods, closures, and imported
functions remain unsupported and must become held-out robustness cases.

Leave-one-complete-fault-family-out evaluation was then added for the learned
executable baselines. Every current feature setting missed all 135 faulty examples
when their fault family was excluded from training, producing F1 of 0. Static and
hybrid features also created false alarms, yielding aggregate accuracy of about 0.333;
runtime-only features yielded accuracy of 0.500. Dataset holdout remains perfect
because the evidence vocabulary is shared across datasets. This contrast demonstrates
that dataset generalization is not fault-mechanism generalization and prevents using
the easy dataset-holdout number as the principal claim.

Selective-risk curves were added at 100%, 80%, 50%, and 25% coverage. On held-out
fault families, abstaining by logistic-regression confidence did not reliably reduce
error. Static and hybrid models reached selective risk of 1.0 at 25% coverage, meaning
their most confident quarter contained only wrong decisions in the pooled evaluation;
runtime-only risk stayed near 0.5 across coverage. This is a serious calibration and
distribution-shift failure: ordinary confidence is not a trustworthy abstention signal
for unseen mechanisms. Any future uncertainty component must be evaluated against this
failure rather than advertised from in-distribution calibration alone.
