# Search-library capture and a negative baseline result

## Implemented boundary

`capture_grid_search` executes scikit-learn GridSearchCV with explicit materialized
splits, dense inputs, accuracy scoring, a single worker, and refit disabled. It
captures validation-row identities and mean candidate scores and checks its chosen
candidate against the library's best index. Users supply dataset/row identity and
pre-boundary history, not a final fault label. Missing pre-boundary history defaults
to incomplete, so absence of overlap alone cannot certify a report.

Bad positional splits, duplicate row identities, overlapping training/validation
positions and noninteger identities are rejected. This is a deliberately restricted
adapter, not a general GridSearchCV replacement. It does not capture preprocessing
leakage, estimator-internal data access, adaptive parameter-grid construction,
manual decisions, or refitting. The selected object describes a configuration's
selection history; it is not a fitted final estimator.

Reference checked: [GridSearchCV API](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.GridSearchCV.html).
Experiments used locally installed scikit-learn 1.9.0; the live documentation may
describe a newer patch release. No private library interfaces are used.

## Measured development experiment

Three bundled datasets × three seeds × two prior-history conditions = 18 searches.
Each search fits three tree configurations over three stratified folds: 162
candidate-fold fits. For each search, probe three report origins: overlapping,
disjoint, and partially overlapping. These are constructed origin probes with a
placeholder scalar, not measured final model accuracies. In particular, the disjoint
identity is an artificial unused ID, not a newly collected test observation.

The comparator uses validation-row roles directly from the supplied split arrays,
plus the same prior-completeness flag. It is a simple local baseline, not a
reimplementation of the published ASE detector.

- 54 report-origin probes; zero disagreements with the split-role baseline.
- Zero candidate-choice disagreements with GridSearchCV across all 18 searches.
- 118 regression tests pass with warnings treated as errors; repository lint passes.

Machine-readable evidence: `results/2026-09-18/search_capture.json`.

```bash
.venv/bin/python scripts/evaluate_search_capture.py \
  --output results/2026-09-18/search_capture.json
.venv/bin/pytest -W error
.venv/bin/ruff check .
```

## What this changes about the paper

This is useful integration evidence but **no demonstrated detection advantage**.
When every candidate uses the same folds in a single search, retaining the union of
validation rows is sufficient for these report-origin queries. A richer dependency
representation cannot claim empirical superiority from this setting. Missing-history
awareness can also be included in a simple baseline; it is not exclusive to our method.

Do not expand this experiment to hundreds of seeds and call that novelty. The next
question is whether independently authored workflows contain report-specific,
multi-stage choices where a single global row-role summary is too conservative or
loses necessary information. Compare against a per-selection row-set baseline too;
if that is equivalent, describe the implementation accordingly, not as a new algorithm.

## Confirmation-study gate

Before collecting confirmation outcomes, freeze the sampling and annotation protocol:

1. Source publicly available Python model-search workflows with pinned revision and
   license. Exclude previously examined ASE notebooks from unseen confirmation.
2. Log every screened source, including exclusions and why; group related examples
   from the same repository/author to prevent pseudo-independent sample counts.
3. Separate unmodified source, required adaptation, and injected faults. Do not call
   an injected problem a naturally occurring external fault.
4. Have both researchers independently trace which scores influence which choices
   and which rows support the report. Record unknown human decisions as unknown.
5. Freeze labels before revealing detector outputs. Preserve disagreement and
   adjudication records; no synthetic placeholder may stand in for a human review.
6. Run published tooling where compatible and record failures/unsupported categories.
   Compare matched supported cases and report coverage over all eligible workflows.

The project remains unready for a methods-paper submission until this study supplies
a defensible contribution. Negative replication/empirical findings are possible, but
this small authored pilot alone does not establish a publishable empirical result.
