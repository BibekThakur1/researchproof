# Persisted score provenance: implementation checkpoint

## What changed

`researchproof.score_store` now saves and loads model-selection evidence in a
versioned JSON envelope. Each record carries the model identifier, scalar score,
dataset-qualified evaluation row identities, prior selection history, and explicit
completeness flags. The file contains evidence, not executable model objects.

This supports an explicit workflow boundary: one process evaluates candidates and
saves evidence; another loads that evidence and selects a candidate through
`choose_model`. This is not automatic tracing of arbitrary Python programs.

## Checks actually run

Eight new regression tests cover:

- A separate Python process loading saved scores, selecting a model, identifying
  reuse of the selection rows, and distinguishing a disjoint reporting set.
- Removal of each of four provenance fields. For a disjoint report, each removal
  produces `insufficient_evidence`, rather than verified absence of reuse.
- A changed scalar score with an unchanged checksum being rejected.
- Preservation of an already selected model's history through a save/load cycle.
- Rejection of fractional row identities, even with a matching checksum.

The full suite passed: **108 tests**, with warnings treated as errors.
Repository lint also passed. These are software correctness checks on constructed
inputs, not independent evidence of detection accuracy or research novelty.

Reproduce from the repository root:

```bash
.venv/bin/pytest tests/test_score_store.py -W error
.venv/bin/pytest -W error
.venv/bin/ruff check .
```

## Interpretation and limits

Persistence need not discard selection evidence when producers and consumers use
this explicit format. Missing evidence must remain visible. An observed overlap is
still a positive witness even when other history is incomplete.

The SHA-256 checksum detects accidental changes; it is not authentication. Someone
can modify both the payload and checksum. The format cannot establish that an
instrumented producer honestly captured every decision. Dataset namespaces and row
identities must remain stable across processes. No external workflow, storage-scale
benchmark, or second-machine reproduction was added in this checkpoint.

## Next experiment, before making stronger claims

Integrate this boundary into a small scikit-learn search workflow with actual model
fits, then independently adapt a separately authored workflow. Freeze the workflow
list and expected audit labels before inspecting detector output.

Question: can score provenance survive evaluation-to-selection handoff without
incorrectly classifying missing history as clean?

Compare scalar-only exports, complete provenance exports, and deliberately stripped
exports. Include selection-set reuse and disjoint final reporting, and measure
capture coverage, false alarms, missed reuse, abstention rate, serialization size,
and runtime overhead. Count workflows, not repeated copies, as the independent units.

A failure to capture ordinary search decisions, excessive overhead, or comparable
performance from a simpler explicit split-role baseline would weaken the proposed
research contribution. Do not call this a novel algorithm merely because it works.
