## Development observations

The explicit sequence and runtime-lineage rules classify all 360 executable cases.
That is evidence that the synthetic traces remain too transparent, not evidence of a
strong detector.

Under leave-one-dataset-out evaluation, the static and hybrid learned baselines reach
perfect classification on the generated traces. Runtime-only classification reaches
0.875 accuracy and 0.857 F1. These values must not be presented as generalization to
real code because the same template vocabulary occurs across datasets.

Under the stricter leave-one-fault-family-out evaluation:

- runtime-only reaches accuracy 0.500 and F1 0.000;
- static and hybrid each reach accuracy 0.500 and aggregate F1 0.333;
- three of four held-out fault families have F1 0.000;
- the apparent nonzero aggregate result comes from false alarms in the train/test
  overlap fold, not reliable unseen-fault recognition.

The 44-case source pilot produces 0.886 accuracy and 0.815 F1 for the shallow AST
baseline under structural-template holdout. The symbolic analyzer classifies the
self-authored pilot perfectly, while removing helper summaries reduces F1 to 0.897.
Because every built-in source case has the same author, these remain development
observations only.

Repeated-test tuning raises reported accuracy by about 0.0073 on average in the
current 45 paired contrasts. This is a controlled development effect, not an estimate
of real-world bias prevalence or magnitude.

## Scientific decision

Continue the project, but stop expanding self-authored toy accuracy. The next useful
evidence must come from a second author and a second machine. If external cases make
the symbolic method fail, preserve those failures and use them to narrow or redesign
the method. If simple rules remain perfect on externally authored cases, a more
complex learned detector is not justified.
